Echo — local-first AI inbox assistant

Echo pulls your real email from any IMAP server, classifies it on your own machine with a built-in AI model, and lets you act on it from a clean web UI. No cloud, no login, no paywall, no third-party AI API.

It is a faithful local-first rebuild of SaneBox’s product:

  • Inbox / Later / News / BlackHole / Snoozed / Reminders / Digest
  • AI triage with plain-English reasons, urgency, follow-up, topics
  • BlackHole a sender to permanently mute them
  • Snooze emails into custom folders
  • Follow-up reminders on threads that need a reply
  • Daily Digest view
  • An 8-page comparison hub for SEO (vs SaneBox, Clean Email, Boomerang, etc.)

Quick start (Node)

# 1. install
npm ci

# 2. build + start (production)
npm run build
npm start
# → http://localhost:3000

# OR for development with hot reload
npm run dev
# → http://localhost:3000

# Use the helper:
./start.sh           # production
./start.sh dev       # dev mode

Connect your real inbox

Once the web app is running, open http://localhost:3000/connect and:

# one-time: install the IMAP client
npm install imapflow

# one-time: configure your IMAP host + credentials
node bridge.mjs --config

# start the sync loop (pulls every 60s by default)
node bridge.mjs

The web UI’s status pill will go from “Bridge offline” to “Live · imap.gmail.com” within a few seconds. Your real mail will appear in the inbox.

The bridge stores your IMAP password in ~/.echo-bridge.json with file mode 0600. It only ever talks to your IMAP host and http://localhost:3000.

Docker

# build and run
docker compose up -d --build

# logs
docker compose logs -f

# stop
docker compose down

The web app will be on http://localhost:3000. The IMAP bridge is intentionally not inside the container — it needs access to your host’s network and your credentials. Run it on your host machine:

# on the host (not in the container)
node bridge.mjs --config
node bridge.mjs

If the Docker container is on a different host than the bridge, set:

export ECHO_BASE=http://<echo-host>:3000
node bridge.mjs

Deploy

Echo is a standard Next.js 14 app. It works on any host that supports Node 20+ or Docker:

  • Vercel — vercel --prod from the project root
  • Railway / Render / Fly.io — point at this repo; they auto-detect Next.js
  • Any VPS — node start.sh behind nginx/caddy
  • Docker — docker compose up -d --build

Required runtime: Node.js 20 or later. No databases, no env vars, no API keys.

How the AI works

lib/classifier.ts is a real, multi-signal feature-engineered classifier running in the local Node process. For every email it computes:

  • Sender reputation — known productivity vs. known newsletter vs. suspicious TLD
  • Urgency signals — “asap”, “by Friday”, “EOD”, “deadline”, “blocking”
  • Follow-up intent — “need your sign-off”, “circling back”, “did you get”
  • Personal cues — signed name, casual greeting, short body, personal domain
  • Promo / spam signals — “70% off”, “free spins”, “click here to claim”

It returns a category, a numeric score (-1..+1), an urgency %, a plain-English reason, a suggested folder, an optional follow-up delay in days, an unsubscribe flag, and the top 5 topics.

No third-party AI API is called. No email leaves the device.

Privacy

  • No login, no account, no analytics, no telemetry
  • Email is processed in memory only; closing the server discards it
  • The bridge stores your IMAP password in ~/.echo-bridge.json (mode 0600)
  • The web app only ever talks to localhost:3000; the bridge only ever talks to your IMAP host + localhost:3000
  • The classifier is shipped as part of the app and is fully open to read
